# obfusk

基于 Babel 的 JS/TS 前端代码混淆与防篡改工具,为保护计价、风控等核心前端逻辑设计。
竞品扒代码的应对思路不是"绝对不可读"(不存在),而是把逆向成本拉到重写成本之上,
并让被改动过的产物直接停止工作。

## 保护能力

| 能力 | 说明 |
|------|------|
| 标识符重命名 | 作用域感知(`scope.rename`),所有引用同步更新;导出 API 名保留,内部 helper 全部抹成 `_0x…` |
| 字符串加密 | 字符串字面量 UTF-8 → 按字节 XOR(每次构建随机 key)→ base64,集中入数组,引用点替换为解码调用,运行时带缓存解码 |
| 控制流平坦化 | 直线型函数体改写为 `while + switch` 状态机,执行顺序只编码在分发数组中 |
| 死代码注入 | 恒假不透明谓词包裹的垃圾分支 + 永不调用的垃圾函数,与真实代码一起参与后续混淆,无法区分 |
| 完整性自校验 | 构建期对全部顶层函数生成代码算 FNV-1a 哈希嵌入产物;运行时用 `Function.prototype.toString()` 重算比对。重新格式化或改动任意字符即触发降级,导出函数停止工作 |
| 调试器检测降级 | `debugger` 语句计时 + 浏览器 DevTools 窗口尺寸检测;命中后置降级标志,导出函数失效 |

## 强度档位

| 档位 | 重命名 | 字符串加密 | 死代码 | 控制流平坦化 | 完整性校验 | 调试器检测 | 适用 |
|------|--------|-----------|--------|--------------|-----------|-----------|------|
| `light` | ✓ | ✓(≥4 字符) | — | — | — | — | 性能敏感的边缘页面 |
| `medium` | ✓ | ✓(≥2 字符) | ✓ | — | — | ✓ | 默认发版 |
| `heavy` | ✓ | ✓(全部) | ✓ 更多 | ✓ | ✓ | ✓ | 计价/风控核心模块 |

变换顺序:控制流平坦化 → 死代码 → 字符串加密 → 重命名 → 调试器检测 → 完整性校验。
平坦化最先做(死代码的 if 分支会破坏直线型函数体前提);死代码在字符串加密前注入,垃圾代码才能被后续变换一起混淆;完整性校验最后做,哈希覆盖接近最终形态的代码。

## 使用

```bash
npm install

# 构建(默认 heavy 档)
npm run obfusk -- build fixture/pricing.ts -p heavy -o dist/pricing.obf.js

# 固定 seed 可复现构建
npm run obfusk -- build fixture/pricing.ts -p medium --seed 12345

# 跑测试:原始测试集 + 三档混淆产物跑同一测试集 + 防篡改测试
npm test

# 量化体积与性能损耗
npm run bench
```

## 实测损耗

对 `fixture/pricing.ts`(计价 + 风控,~1.7KB)在本机(Node 26)的实测,工作负载为 10 万次 quote + riskScore + decide 混合调用:

| variant  | raw size | raw x | gzip | gzip x | time/100k ops | slowdown |
|----------|----------|-------|------|--------|---------------|----------|
| baseline |     1762 | 1.00x |  755 | 1.00x |          5.6ms | 1.00x |
| light    |     2203 | 1.25x |  944 | 1.25x |          6.0ms | 1.08x |
| medium   |     3672 | 2.08x | 1484 | 1.97x |          7.5ms | 1.35x |
| heavy    |     5154 | 2.93x | 1982 | 2.63x |         12.5ms | 2.24x |

解读:light 档几乎无感(+8%);heavy 档体积 ~2.9x、耗时 ~2.2x,对单次毫秒级的计价调用来说绝对增量可忽略(每次调用约 +0.07μs),适合只用在核心模块上而非全量代码。`npm run bench` 可复现。

## 防篡改行为

- `integrity.mode: 'throw'`(默认):检测到篡改后,调用任何导出函数抛 `Error: invalid state`
- `integrity.mode: 'corrupt'`:静默返回 `undefined`,让攻击者难以定位检查点

校验覆盖模块顶层所有函数(含字符串解码器、helper、垃圾函数)。注意:

1. **混淆必须放在构建链最后一步** —— 之后再过 terser/prettier 会改变源码文本,误触发自校验。
2. 顶层常量对象(如费率表)不在函数哈希覆盖范围内,属于已知边界;如需覆盖可将其包进函数。

## 已知限制

- 控制流平坦化只处理直线型语句序列(表达式/声明/末尾 return),含 `if/for/try` 的函数保守跳过,保证语义不变
- 调试器检测是"提高成本"而非"阻止":攻击者单步绕过检测点总是可能的,目标是让自动化扒取和批量分析失效
- 浏览器端 `setInterval` 定时巡检;Node 环境下只执行一次性检查,不影响服务端渲染与测试

## 项目结构

```
src/
  obfuscator.ts          管线编排
  presets.ts             三档强度预设
  transforms/
    rename.ts            标识符重命名
    strings.ts           字符串加密
    cff.ts               控制流平坦化
    deadcode.ts          死代码注入
    integrity.ts         完整性自校验
    debugGuard.ts        调试器检测降级
fixture/pricing.ts       示例业务模块(计价 + 风控)
tests/                   原始测试集 + 混淆产物同测 + 防篡改测试
bench/bench.ts           体积/性能损耗量化
```
